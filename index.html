Case study — full-stack product build

Navaar Studio: an Urdu video creation platform, built end to end

A browser-based tool for turning Urdu poetry and lyrics into short, shareable videos — with real user accounts, a secure database, and subscription billing behind it.

What it does

Navaar Studio lets someone type a line of Urdu or English poetry, choose a visual mood, typography, background, and voice direction, and export a real HD video — rendered entirely in the browser with the Canvas API, no external video service involved.

A second tool, the Photo + Lyrics Video Maker, takes a person's own photos and lyrics and produces a lyric-video-style export with six selectable cinematic layouts and a user-supplied audio track.

What I built

Frontend

Responsive landing page and interactive studio in vanilla JS. Real-time canvas rendering and export via the MediaRecorder API, RTL-aware Urdu/English typography switching, and a client-side photo slideshow engine with synced captions and audio mixing.

Backend

A Node.js and Express API handling saved projects, checkout sessions, and subscription webhooks — deployed as a standalone, publicly reachable service.

Database

A Postgres schema on Supabase with Row Level Security enforced at the table level, so a user's saved projects and subscription status are isolated from every other user by default — not just by application logic.

Payments

Originally scoped for Stripe; pivoted to a Merchant-of-Record provider after discovering a regional account restriction, avoiding a manual international tax-compliance build.

Architecture

The frontend never touches the database directly — every write goes through the API, which is the only thing holding service-level credentials.

Browser (GitHub Pages) │ ├─ Supabase Auth ── sign up / sign in ├─ Supabase DB ── saved projects, RLS-protected │ └─ Express API (Railway) ├─ /api/projects → save / list / delete a project ├─ /api/checkout → start a subscription checkout └─ /api/webhook → sync subscription status

A few decisions worth naming

No external AI video service

Video generation happens entirely client-side via Canvas and MediaRecorder. Zero per-video compute cost, and no dependency on a third-party rendering API staying online.

Security at the data layer, not just the app layer

Row Level Security means a bug in the API can't leak another user's projects — the database itself refuses the query.

Free-tier infrastructure by design

Database, backend hosting, and frontend hosting were all chosen and configured to run at zero fixed cost during early validation, before any revenue exists.

Adapting around a real constraint

Stripe doesn't support Pakistan-based accounts. Rather than stall the build, the billing layer was re-scoped around a Merchant-of-Record provider that handles global tax compliance out of the box.
